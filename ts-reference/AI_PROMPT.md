# 執務表生成 AI プロンプトテンプレート

## 使い方

このプロンプトを Claude API (claude-opus-4-7 等) に投げることで、
前日実績 + 今日の警防態勢から執務表を自動生成させる。

fire-duty アプリの「AI ボタン」から呼び出す想定。

---

## プロンプト本文 (システムプロンプト)

```
あなたは消防署の執務表 (通信指令 / 受付 の一次指定者) 作成の専門家です。
前回の執務表と今回の警防態勢を元に、今回の執務表を作成してください。

# 表の構造
- 25時間帯: 8:40〜9, 9〜10, 10〜11, ..., 22〜23, 23〜24, 0〜1, ..., 7〜8, 8〜8:40
- 2列: 通信指令 / 受付
- 受付 8:40〜9 は 斜線 (必ず空文字 "")

# 絶対ルール
- 通信と受付は同時刻で別人
- 4時間以内の同一人物再登場は原則避ける
  (どうしても候補がいない時のみ許容、消防士は例外)
- 12〜13時 と 17〜18時 は別人

# 固定枠 (警防態勢から自動決定)
- 通信 8:40〜9, 9〜10 = その日の「残留」ポジションの人
- 受付 9〜10, 8〜8:40 = その日の「署隊長伝令」ポジションの人
- 通信 10〜11 = その日の「伝令」または「通信担当」
- 受付 10〜11 = もう一方 (伝令 or 通信担当)

# 専属カラム
- 残留の人は 通信 のみ (受付に入らない)
- 署隊長伝令の人は 受付 のみ (通信に入らない)
- 両者とも固定枠以外でも自分のカラム内でローテ登場

# 階級による配置傾向
- 司令・司令補: 通常 執務表対象外 (勤務に入らない)
- 士長: 通信優先
- 副士長: 受付ベース、ローテ不可時は士長が受付に下りる
- 消防士: 電話対応難のため通信は原則不可、受付ベース
  前回と同時間帯になっても許容 (先輩ローテ優先)

# 深夜ローテ (slot 14..20 = 22時〜5時)
- 前日の「1つ下」スロットの人を今日のスロットに入れる
  例: 前日 slot 17 (1〜2時) の人 → 今日 slot 16 (0〜1時)
- 士長階級を優先してローテーション

# 救急ローテの人
- 前回執務表に名前が出ていない (救急で出動していた) 人は
  今回どこに入れても前回被りにならないため、穴埋めに使える

# ブロック条件 (その時間帯に入れない)
- 食当: 14〜15, 15〜16, 16〜17 ×
- 当直: 18〜19, 19〜20, 6〜7, 7〜8 ×
- 休暇/研修/出向/警防力/救急隊: 全時間 ×
- 日中救急: 8:40〜9 〜 17〜18 まで全て ×
- 夜救急: 18〜19 〜 8〜8:40 まで全て ×

# 配置の流れ (参考)
1. 固定枠 (残留・署隊長伝令・伝令/通信担当) を先に押さえる
2. 深夜 22-5時 を前日から1つ上にスライド
3. 日中 10-17時 の士長以上をローテ、未勤務にならないよう配慮
4. 残りを通常ローテで埋める
5. 12勤と17勤が同一なら入れ替え

# その他
- 10〜17時 は 士長以上 の人は最低1回は入れる (消防士は未勤務もやむなし)
- 深夜 (22時〜4時) は一人1回まで

# 入力形式
ユーザーは以下の情報を提供します:
- 今日の警防態勢 (氏名 → ポジションのマッピング)
- 前回の執務表 (テキスト or 画像)
- 休暇・当直・食当・研修/出向・警防力 の該当者

# 出力形式
必ず以下の JSON で返してください:

{
  "cells": {
    "通信": [ "氏名", "氏名", ..., 25個 ],
    "受付": [ "", "氏名", ..., 25個 (最初は "" 固定) ]
  },
  "notes": [
    "注意点があれば自由形式で列挙",
    "例: 伊藤が4時間以内に再登場しています",
    "例: 消防士○○が10-17時未勤務です (構造的制約のため)"
  ],
  "confidence": 0.85
}
```

## 呼び出し例 (擬似コード)

```javascript
import Anthropic from "@anthropic-ai/sdk";
const client = new Anthropic();

const systemPrompt = /* 上記のプロンプト本文 */;

const userInput = `
# 今日の警防態勢
- 原田 陽一郎 (司令補): ポンプ隊
- 梅村 侑志 (司令補): 救助隊
- 小西 隼人 (士長): ポンプ隊, 当直
- 鍋谷 昇 (士長): はしご隊
- 山川 敦史 (士長): 残留
- 金子 卓磨 (副士長): 署隊長伝令
- 長田 智紀 (士長): 伝令
- 和田 浩司 (副士長): 通信担当
- 村山 哲也 (士長): 食当
- 中村 太一 (消防士): 休暇
...

# 前回執務表 (2026-04-16)
通信: 山川, 山川, 長田, 原田, ..., 小西  (25個)
受付: "", 金子, 和田, 長友, ..., 金子  (25個)
`;

const response = await client.messages.create({
  model: "claude-opus-4-7",
  max_tokens: 2000,
  system: systemPrompt,
  messages: [{ role: "user", content: userInput }],
});

const json = JSON.parse(response.content[0].text);
// json.cells を執務表に反映
// json.notes を警告として表示
```

## 精度について (正直な見積もり)

| 項目 | 期待精度 |
|---|---|
| 固定枠 (残留・署隊長伝令・伝令) の配置 | 95%+ |
| 専属カラムの順守 (残留は通信のみ等) | 90% |
| 4時間間隔ルール | 70-80% |
| 深夜 1つ上スライド | 70% (明示指示で向上) |
| 前日同時刻重複回避 | 80-90% |
| 階級配置 (消防士→受付等) | 85%+ |
| JSON 形式の正確さ | 95%+ |

**総合**: 初回 70-80% 正しい配置。**残り 20-30% は人が微調整**する前提で
使うと、手作業比でトータル 10 分 → 2 分 くらいの短縮効果。

## 精度を上げるコツ

1. **Extended Thinking モード有効化** (claude-opus-4-7 の場合 `thinking: { type: "enabled", budget_tokens: 5000 }`)
   → 複雑な制約の整合チェックが入念になる
2. **Few-shot 例を入れる** (過去に上手く行った例を1〜2個プロンプトに)
3. **ツール使用 (Tool Use)** で validate 関数を LLM から呼ばせる
   → 出力後に自己検証して修正
4. **2段階プロセス**:
   - Step 1: LLM に下書きを出させる
   - Step 2: 前回の数値検証スクリプトで警告チェック
   - Step 3: 警告があれば再度 LLM に投げ直して修正

## 写真 OCR (前回執務表を画像で渡す場合)

Claude Vision API で画像を content に含めて送る:

```javascript
messages: [{
  role: "user",
  content: [
    {
      type: "image",
      source: { type: "base64", media_type: "image/jpeg", data: base64Img }
    },
    {
      type: "text",
      text: "この画像は前回の執務表です。この内容を踏まえて今回の執務表を作ってください。"
    }
  ]
}]
```

ただし OCR 精度は **手書き・薄い印字・漢字認識で劣化**するので、
写真はあくまで補助として使い、**警防態勢データは構造化された JSON で渡す**
のが実用的。

## テスト手順

1. このプロンプトを Claude の Web 画面 (claude.ai) に直接貼る
2. 過去の警防態勢と執務表データをユーザーメッセージとして入れる
3. 生成された JSON が妥当か目視確認
4. 警告メッセージと実際のルール違反が一致するか確認
5. fire-duty の AI ボタンに組み込む際は、この結果を UI に反映

## 実装に向けての注意

- **API キーの扱い**: 端末ローカル or Cloudflare Workers 経由。ブラウザ直接呼びは鍵露出
- **料金**: Opus で 1回 1-5 円程度。月100回で 100-500 円
- **タイムアウト**: 複雑なプロンプトで 10-30 秒。UI でローディング表示
- **エラー時のフォールバック**: AI失敗 → ローカルスケジューラで生成
